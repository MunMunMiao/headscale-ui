# 浏览器首轮验证（非最终整体验收）

## 范围与时点

本轮使用 `preview_start` 启动项目现有 `scripts/tag-lifecycle-preview.ts`，端口 4187；独立 Headscale 0.29.4、三台真实 Tailscale 客户端及随机测试凭据，未复用/reset 已有 playground。通过一次性、同源受限初始化入口建立临时资料；这不是再次进行普通用户首次配置研究。

**本文件记录的是独立审阅提出 I1—I3/M1—M3 之前的正常路径。** 随后的并发/失效分支回归仍需修正，因此这些正向结果不能当作最终补丁全部正确的证明。原 G01/G02 没有实施。

浏览器视口以 DOM 的 CSS 尺寸读回为准；截图由应用按显示区域缩放，文件像素不代表 CSS viewport。JavaScript 只用于 DOM、焦点、布局和滚动值检查，没有注入应用数据或代替 UI 写入。

## 运行及工具限制

- 第一次自动打开页面的控制台历史出现 `Invalid hook call`，Vite 同期日志显示 `effect` 依赖优化并 reload；之后仅会话资料不可用的唯一原因没有独立定位。该尝试没有记为通过，按启动器既有方式停止并重建独立 fixture。
- 第二次初始化及上述交互的新文档控制台检查没有错误。没有把旧文档日志清空后声称从未报错，也没有据此修改产品代码或伪称冷启动根因已修复。
- 该浏览器工具的页面网络缓冲未完整记录 SharedWorker 的 API 请求，且会丢弃早期条目。因此不以“未找到 /tags 请求”单独证明全程零写入；正常路径的原集合读回、UI 结果及组件测试共同限定证据。发布则另做了隔离后端 GET 读回。
- 应用窗口当时未在前台会话视图中打开，不能用本次等待时长评估性能。可访问性树、焦点、CSS 尺寸与最终画面逐项核对。
- 为处理独立审阅发现的回归，已关闭两张本轮浏览器页、清除 viewport emulation 并停止预览。两个子代理继续处理对应源码与真实 RED/GREEN；后续完整检查与最终预览另记。
