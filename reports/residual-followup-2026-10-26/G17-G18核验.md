## G18：最终真实隔离验证通过

[可复跑探针](g18-ssh-probe.ts)、[完整结果](g18-ssh-results.json)、[脱敏执行日志](g18-ssh-run.log)。最后一轮约 16.5 秒，实际退出 0；协调者核对脚本的真实 SSH 调用、严格 hostkey、stdout marker 判定、daemon 权限断言及结果文件。

| 分支 | 正常审批 API | 真实执行结果 |
| --- | --- | --- |
| root、零 capability，批准 | 200 | access granted → be-child → EPERM，退出 1，无 marker |
| 同 UID 非 root，批准 | 200 | access granted → be-child → Session complete，远程 marker 正确，退出 0 |
| 非 root 独立新请求，拒绝 | 200 | access denied，退出 255，无 granted、child 或 marker |

三个 SSH daemon 均直接读取 `/proc/1/status`：source/root 的 UID/GID为0，非root为10000，非root实际Groups严格为单个10000；CapInh/Prm/Eff/Bnd/Amb全零、NoNewPrivs=1、Seccomp=2。没有 CapAdd、GroupAdd、TUN、privileged、hostNetwork或ptrace，保留 `StrictHostKeyChecking=yes`。LSM空读回仍标记未知，不以exec shell冒充daemon；控制面复用原fixture，其默认能力不冒充SSH peers的零能力。

**修正的是隔离验收目标配置：**daemon与登录账户采用相同非root UID/GID、完全一致的补充组，自有可写statedir/socket。不改上游二进制或安全检查，也不加权限。Docker已包含primary GID，重复 `--group-add 10000` 会让组向量变成两个相同项，最终删除此冗余项并保留严格断言。

前三次失败及清理记录保存为 `g18-ssh-attempt1-*`、`g18-ssh-attempt2-*`、`g18-ssh-attempt3-*`，分别涉及固定版本status字段/状态目录、stderr日志采集以及重复补充组；不伪装为全程一次通过。最终所有自有SSH容器、控制面容器、网络及卷均为零，凭据目录随fixture清理。文件权限0600，定向lint零warning、脱敏self-check通过。

**结论与限制：**不应再笼统归为“SSH批准失败”。真实请求已证明批准、远程命令、独立拒绝三层可区分，也证明零能力同UID非root路径可用；本轮是正常API驱动真实SSH，不是UI重跑。当前Linux/arm64，旧记录为Linux/amd64，不能声明旧环境已修或其唯一失败系统调用已实证；未覆盖root成功登录、PTY或文件传输。可复用配置与停止条件已补充到 `e2e/ai/README.md`，没有对宿主或生产环境做权限变更。
