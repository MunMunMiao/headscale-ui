## V01：重复邮箱造成既有策略 principal 歧义和真实连接中断

- 来源：UX04，候选编号 `ux04-F01`。
- 影响：高。一个普通成员创建操作可以影响既有允许规则下的真实设备访问；后续策略提交也会被拒绝。
- 验证状态：**已在 UX04、UX11 两套独立 namespace、后台和客户端环境复现；协调者已检查原始状态、HTTP 记录及截图，并对两套证据运行一致性断言。主协调者未亲自操作浏览器重演，不将成员独立复现误称为本人重演。**

### 已检查的证据

- [重复邮箱用户创建后页面](ux04/evidence/ux04-duplicate-email-created-no-warning.png)：Alice 和新用户显示同一个 `alice-ux04@example.test`。
- [策略提交失败页面](ux04/evidence/ux04-duplicate-email-policy-rejected.png)：Headscale 明确返回 `multiple users found: token "alice-ux04@example.test"`。
- [第二轮创建后状态](ux04/evidence/ux04-state-duplicate-email-repro-created.json)。
- [第二轮删除后状态](ux04/evidence/ux04-state-duplicate-email-repro-recovered.json)。
- [真实网络观测](ux04/evidence/ux04-network.jsonl)，第二轮关键 label 为 `collision-repro-no-policy-write`、`collision-repro-service-alive` 和 `collision-repro-delete-restored`。

### 协调者断言

以下断言全部通过：

1. 第二轮创建后、删除后保存的 policy 内容完全相同；该轮未靠另一份策略解释恢复。
2. 相同邮箱的用户数量由 2 变 1。
3. `client-a → 100.64.0.2:8081` 通过真实 Tailscale HTTP proxy，在重复用户存在时超时；删除重复用户后返回 `ux04-client-b`。
4. 同一时间 `client-b` 的本机服务正常，返回相同标识；不是目标服务停止导致的假阴性。

这组证据支持“只创建歧义身份即可影响既有策略解析”的故障链。尚不能只据此推断所有重复邮箱、所有策略或所有版本都会失效，也不能把根因全归于 UI：后端接受了重复身份且策略解析拒绝歧义引用；UI 未在这个危险组合中提供阻止或充分预警。

## V02：真实出口数据面对照通过，不把私网目标超时概括成出口功能故障

UX07 的独立证据：

- [批准后的公共 HTTP](ux07/evidence/public-exit-approved.json)：同一 client-a 的真实 tailscaled HTTP proxy 请求 `http://example.com` 返回 HTTP 200；对应出口 peer 的 Tx/Rx 均增加。
- [撤销后的相同请求](ux07/evidence/public-exit-revoked.json)：仍选择同一出口，但请求超时，观测期间该 peer Tx/Rx 均不增加。
- [重新批准恢复](ux07/evidence/public-exit-restored.json)：相同 URL、相同 transport 恢复 HTTP 200，出口 peer Tx/Rx 再增加。

协调者已运行断言验证三者 URL/transport 一致、成功/失败/恢复状态与收发计数对照，全部通过。这是一次实际出口数据面验证，不只是 approvedRoutes 或按钮状态验证；不据此宣称吞吐、IPv6 或所有出口场景都已覆盖。

多名成员经出口访问隔离 ClusterIP 持续超时。这一私网目标分支未定位，保留为环境/场景限制；不能因该目标失败就判定 UI 或整个出口功能失败，也不能用公共 HTTP 的通过反过来伪称私网分支通过。

## V03：真实 SSH 审批与拒绝已执行，批准后的远程命令受环境权限阻塞

来源为 UX11 的 [SSH 原始记录](ux11/evidence/ux11-ssh.txt)、[批准页面](ux11/evidence/ux11-08-real-ssh-approved.png)、[拒绝页面](ux11/evidence/ux11-09-real-ssh-rejected.png)及本人报告。请求由真实 `tailscale ssh` 产生，未通过 debug API 伪造；实验设施通过正常管理接口设置 SSH `action=check`，不把网络端口 22 的允许规则等同于 SSH 会话授权。

批准分支被客户端实际消费，目标记录 `access granted`，随后远程命令因 `operation not permitted` 失败；拒绝分支记录 `access denied`。协调者已确认原始日志包含这些不同阶段的标记。容器无 capabilities，未为完成 shell 而扩大权限或修改宿主。此项仅确认真实审批/拒绝链路，不宣称完整 SSH 命令执行成功，也不直接把命令阶段的权限错误归为 UI 缺陷。
