## 6. 体验观察、工具和环境问题

这些观察不计作已确认功能缺陷。

- 退役检查能指出 active service 标签存在设备和策略引用，并阻断退役。对空 owners、无设备/邀请/可见引用的 next 标签，勾选外部部署核对后仍只给出泛化阻断句，没有呈现具体未满足条件；刷新数据源后仍需重新勾选。未确定是定义本身仍存在还是其他条件，不能声称退役逻辑错误。通过专门“仅移除策略定义”入口可正常删除。
- 首次迁移目标准备草稿被服务器策略变化保护拒绝，草稿保留。没有其他成员操作本环境的证据，也未确定变化来源。按页面提示丢弃并重新创建后发布成功；不能把这个单次保护事件直接定为并发控制误报。
- 默认 Give access 会先勾选 SSH。若在添加自定义端口之前先取消最后一个 SSH 选项，该访问者行随最后服务消失；恢复办法是重新选择访问者，先填自定义端口再取消 SSH。共享工具 setChecked 因控件消失而超时属于工具动作结果，不能据超时直接判产品崩溃。
- 共享 capture-key 首次取得过短片段而不是完整凭据，使用本人私有、绑定相同真实 Chrome 的可见控件读取脚本恢复。产品生成的完整密钥可正常注册两台设备。
- 浏览器 helper 的 batch 子项 tab 字段并不切换当前页，而且 CDP 重连时页面编号可变。会话验证改用同一次 CDP 连接中按页面 URL 识别两页，避免把工具索引错误当共享会话缺陷。
- Tailscale set 不接受 --advertise-tags；改按正常 tailscale up 契约操作。强制重新认证时客户端要求显式保留全部非默认参数，按它给出的命令补齐后成功。
- 出口数据面失败的归因未知，单独列为环境/上游/配置待区分项，不归入 UI 缺陷。
