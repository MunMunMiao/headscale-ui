## 3. 从零开始的实际操作顺序

1. 空资料打开入口，创建 ux05 标签实验 资料，填写服务器和管理 key，设置资料加密密码，Save and unlock 后进入空总览。明确资料密码保护本地服务器凭据，不是 Headscale 用户登录密码。
2. 在 Users 创建 ux05-owner 和 ux05-worker；后者改名为 ux05-operator。实际查看详情和搜索。其仍拥有 client-b 时，删除确认显示 Devices: 1 并禁用 Delete user。另创建 ux05-empty，再实际删除，验证无设备删除路径。
3. 在 Auth keys 查看默认值：约七天有效、Reusable 未选、Ephemeral device 未选。创建首把单次 key 和第二用户的可重复 key，通过真实客户端命令接入 client-a、client-b。两者 Running、Online，地址分别为 100.64.0.1 和 100.64.0.2。单次 key 变为 Used，可重复 key 使用后仍为 Ready。
4. 完成 Machines 详情、搜索、在线筛选、改名。将 a 显示名称改为 ux05-client-a-migrating；空名称时保存被禁用。
5. Access 创建 group:ux05-ops，成员 ux05-owner；建立 tag:ux05-old 和 tag:ux05-keep。旧标签 owners 指向运维组，并单独添加 ux05-operator@ 到标签设备的 8081 访问规则。标签定义没有自动关闭原始隐式放行。执行 Check policy、完整 before/after 审阅和发布；刷新重新解锁后读回仍存在。
6. 将 a 的完整标签集合设为 keep+old，经过个人身份转标签身份确认，再确认完整替换。独立读回显示 tagged-devices 身份和两个标签。
7. client-b 广告本成员目标 10.42.0.5/32 及双栈默认出口路由。经 Routes 审批和撤销；子网路径获得实际前后对照。出口路径做了进一步恢复尝试，但没有取得阳性。
8. 创建包含 keep+old 的可重复无个人 owner 标签 key，作为旧部署入口。通过旧标签 Live tag maintenance 准备空的新定义 tag:ux05-new，再显式配置 owners 与 8081 规则，不将旧授权自动合并到新身份。
9. 删除双栈全开放规则后，使用新建 Tailscale TCP 验证 a→b:8081 被拒绝，而 b→旧标签 a:8081 获得 HTTP 200；再通过 UI 添加精确 IP/端口允许规则，a→b 同源同端口恢复 HTTP 200。
10. 通过 Stop known registration entrances 进入旧标签 owners 管理，移除运维组 owner 并发布。b→a 新连接仍 HTTP 200，验证取消申请授权不等于回收已有访问权限。
11. 在迁移维护中指定现有新身份。Review device tags 只打开只读详情，未进入目标集合编辑器。通过正常 Machines 菜单恢复，手工将 keep+old 改为 keep+new，审阅 +new、−old，保留 keep。提交后 b→a 的新建 TCP 仍返回 HTTP 200。
12. 创建 keep+new 的替代可重复 key，并实际强制重新认证 a。随后到期、删除旧标签 key；已有设备仍可访问。之后在设备记录删除后再次使用旧 key 注册，返回 invalid pre auth key。
13. 退役检查先准确显示旧 ACL 引用。单独移除该引用并发布后，设备、邀请、引用均空，外部核验勾选后仍只有通用阻塞文本。关闭检查，从卡片删除空定义并发布。最终独立 policy get 确认不包含 tag:ux05-old。未获得 UI 的退役完成状态。
14. 从设备编辑器选择 Restore personal identity。按提示在 a 清空 advertised-tags 并触发真实非 auth-key 强制重认证，获取实际请求。经页面确认备用管理通道、目标用户 ux05-owner、公共服务器和请求归属后批准。Read current state only 最终确认原节点 1、原 IP、用户 1、标签为空，且不再显示 auth-key 关联。客户端 Running。b→a 因不再匹配标签规则而被拒绝，a→b 的独立 IP 允许通道仍成功。恢复身份不被描述为保证保留 ID/IP 的通用契约，本轮恰好保留。
15. 实际将 a 到期，列表变为 Expired；再 Disable expiry，恢复 Never 和 Running。最后从 UI 删除 a 的设备记录，列表只剩 b。
16. 在资料菜单的 Server settings 创建一把非当前 API key，实际到期并删除，未操作当前会话 key。执行 Backfill，返回 No changes were needed。
17. 修改资料加密密码，旧密码解锁失败，新密码解锁成功。第二标签页直接共享解锁；有另一页存活时刷新保持会话；退出使两页均锁定。另验证只有一页时刷新会重新锁定，页面有明确解释。
18. 切换简体中文和深色主题，观察实际 lang=zh-Hans 与 dark=true，再回到英文。创建临时标签草稿后 Discard changes，确认没有发布。
19. 经 UI 确认并清除本人的全部本地资料。独立读回仍有两名 Headscale 用户、一台设备和一把管理 key，证明清除本地资料并不删除服务器资源。最后删除本人创建的临时秘密及脚本。

## 6. 真实客户端与网络验证

### 接入

- client-a：Running、Online，100.64.0.1 / fd7a:115c:a1e0::1，初始 UserID 1。
- client-b：Running、Online，100.64.0.2 / fd7a:115c:a1e0::2，初始 UserID 2。
- 首轮默认放行下，a 访问 b:8081 得到 ux05-client-b，b 访问 a:8081 得到 ux05-client-a。

### 访问规则与标签身份

用新建 TCP 连接的 tailscale nc，发送 HTTP 请求并保留 stdin 两秒以读取响应，不复用 HTTP 代理连接：

- 限制策略时 a→100.64.0.2:8081：退出 143，Terminated，未收到响应。
- 同策略 b→旧标签 a:8081：HTTP/1.1 200 OK，正文 ux05-client-a。
- UI 添加精确 IP/8081 允许后，同源 a→b：HTTP/1.1 200 OK，正文 ux05-client-b，构成恢复阳性对照。
- 删除旧标签 owner 后 b→a：仍 HTTP 200，符合 owners 不回收现有标签权限的契约。
- 迁移为 keep+new 后 b→a：HTTP 200，正文 ux05-client-a。
- 非 auth-key 恢复个人身份后：a 的 UserID=1、Tags=null、Running；b→a 新连接被拒绝，a→b 独立 IP 允许通道仍成功。

注意：限制策略后 HTTP 代理路径仍曾返回成功，与 fresh nc 不等价。未定位是代理实现还是连接保持差异，因此不把代理成功当作策略发布失败，拒绝判定采用新建 TCP 的结果。

### 隔离子网

- 审批前 a 经 Tailscale HTTP 代理访问 10.42.0.5:8081：502 Bad Gateway。
- 审批 /32 后相同路径：正文 ux05-subnet-target。
- a 直接访问 PodIP：Connection refused；b 直接访问同目标：ux05-subnet-target。目标只允许 b，不能用 Kubernetes 直连冒充 Tailscale 转发。
- 撤销 /32 后 a 相同代理路径：download timed out。
- 独立 Headscale 读回可见出口路由成对存在或成对清除；最终 b 的 approved_routes 为空。

## 7. 工具、环境和产品问题的区分

- 共享 capture-key 首次误取列表中已掩码的短前缀，保存长度 24，导致客户端报 key too short。本人只读检查实验 helper 后，使用自己的临时脚本从实际 Auth key created 可见区域取完整 88 字符 key，接入成功。这是采集工具定位错误，不是产品生成了坏 key；没有改共享 helper。
- 一次 setChecked 操作取消唯一 SSH 服务时，访问行随之消失，引起 locator 超时；恢复为先加自定义端口、再取消 SSH。多个候选按钮和跨 CDP 重连后的标签页索引变化也已消歧，不列为产品问题。
- viewport 设置未跨 CDP 重连保持，以实际截图尺寸为准，不夸大响应式覆盖。
- 出口没有阳性，原因未知；未伪装为通过，未归责 UI。
- 改名后的内嵌旧名称有上游 CLI 返回佐证，单独列为一致性观察。
