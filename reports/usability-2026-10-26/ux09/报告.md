## 2. 从零开始的实际操作

1. 首次打开为空资料登录页，新增 ux09 Operations，填写自己的服务器地址和管理 key，设置资料加密密码，保存并解锁。总览显示用户、设备、密钥与待审批路由均为 0。
2. 新建 UX09 Alice 与 UX09 Bob 两名用户。搜索 Alice、查看详情，把其 Headscale 用户名从 ux09-alice 改为 ux09-admin；显示名保持 UX09 Alice。
3. 在 Auth keys 创建 Alice 单次凭据和 Bob 可重复凭据。默认 Reusable 与 Ephemeral 均未勾选，默认期限约为一周。只将生成值保存在成员私有文件，不截图生成密钥页面。
4. client-a 使用单次凭据接入，client-b 使用可重复凭据接入，并广告本人的 10.42.0.24/32、0.0.0.0/0 与 ::/0。两端分别获得 100.64.0.1 与 100.64.0.2，实际客户端状态为 Running、Online。
5. 检查注册后状态：单次 key 显示 Used；可重复 key 在完成一次注册后仍为 Ready。设备列表能够搜索并查看详情，将 client-a 的管理名称改为 ux09-workstation。删除仍有设备的 Alice 被正确阻止，并列出需先处理的设备。
6. 在 Routes 审批隔离 /32，真实请求由失败变为返回 ux09-subnet-target；撤销后再次失败。独立 CLI 读回曾确认 approved_routes 为该 /32。执行出口节点成对审批与撤销；选择出口后的真实目标请求两次超时，未记录出口连通性成功。
7. 在 Access 新建 ux09-ops 团队，将 Alice 加入团队，定义 ux09-server 标签，团队作为客户端申请授权 owner，并配置团队到该标签的 8081 规则。完成 Check policy、完整原文前后发布审阅、发布及刷新读回。
8. 单个解锁标签页刷新后会锁定，并明确说明没有其他页保持解锁。随后打开第二页，在一页重新解锁可共享会话；存在其他已解锁页时刷新能够继续会话。
9. 在两个真实标签页创建独立策略草稿。第二页先发布后，第一页尝试发布旧草稿被正确拒绝；页面展示最新服务器策略，保留未保存草稿并禁用继续发布。取消、丢弃后刷新恢复。
10. 定义 ux09-audit，并给 client-b 分配 audit、server 两个标签。完整目标集确认明确提示个人身份将转成标签身份。之后移除 audit 时审阅完整集合，保留 server。
11. 移除全开放规则及标签访问规则，发布显式空 ACL。client-a 到 client-b:8081 超时，而目标自身 HTTP 服务仍正常。恢复 ux09-ops 到 tag:ux09-server:8081 后，同一来源、目的与端口再次返回正常内容。
12. 浏览标签维护的迁移、停止已知注册入口与退役检查。存在设备依赖时退役被阻止。后续设备不再使用 audit 后，通过策略定义删除入口移除 audit 并发布；这不等同于证明完整身份退役完成。

20. 复现并截图设备搜索进入用户详情后 Close 丢失搜索的问题。删除已完成测试的 client-b，删除 Bob 到期 key，确认 Bob 的 Devices 和 Active auth keys 均为 0 后删除 Bob。

## 4. 已确认产品问题

### UX09-F01：标签替换后进入恢复身份，基线变化确认循环阻塞

严重程度：中等，P2。

前置条件：client-b 已有 audit 和 server 标签。通过 Edit machine tags 移除 audit 并确认服务器写入；成功后编辑器仍打开。

复现：直接点击 Restore personal identity；在真实客户端清空 advertised tags 并强制非 auth-key 重新认证；填写真实请求，选择 Bob，确认公网 login-server、备用通道和请求归属；点击审批。出现基线变化提示后重新勾选请求确认并再次审批，连续三次仍被同一提示阻止。

预期：当前基线稳定后，依页面要求重新审阅确认能够继续；或明确要求关闭刷新，不能引导用户在不可继续的向导中循环。

实际：反复显示 The device identity, tags, policy or server version changed，确认项被清空，无法完成。独立服务器读回仍为标签身份。

恢复：关闭向导，刷新设备列表，从最新设备重新打开 Restore personal identity，填入相同真实请求后成功。最终独立确认 Bob、空标签、注册方式 2；后续数据面也按新个人身份规则验证。

## 5. 体验观察与工具／环境问题（不混记为产品缺陷）

体验观察：
- 同一浏览器的另一个已打开标签页不会即时跟随语言和主题变化。实际读回一页为 zh-Hans/dark，另一页仍为 en-US/light。没有明确同步契约，因此不升级为已确认功能缺陷。
- 给标签访问人配置服务时，取消最后一个服务会使该访问人整行消失；若希望改为自定义端口，先填写端口再取消默认 SSH 更容易成功。
- 连续完成向导及手动刷新时出现两个 Data updated 通知。未造成操作错误，仅记录重复反馈观察。
- 旧草稿发布保护、个人身份转换警示、密钥到期与设备退役区别等文案较明确；这些安全确认并未被当成阻塞缺陷。

工具问题：
- 批处理只识别顶层 tab；最初把 tab 放到子动作导致动作仍在默认页，后来改用顶层 tab，重新执行真正的跨页草稿实验。错误尝试没有作为共享草稿产品行为证据。
- 自定义复选框取消最后一个服务后目标行消失，setChecked 等待报错；读回页面后按普通 click 和正确顺序继续。
- 对话框关闭动画中同名按钮短暂被工具判为不唯一，等待并按已发现的确认控件消歧后继续，不记产品缺陷。
- tailscale set 不支持 advertise-tags；改用正常 tailscale up，并在需要时产生真实强制重新认证请求。
- 最初 tailscale nc 的一次输出为空，即使进程退出 0 也没有作为连通性通过。随后全部有结论的数据面验证改用客户端自身 HTTP 代理与 wget，要求返回实际目标内容。

环境／运行时受阻：
- 初始默认放行策略下，出口审批后 client-a 选择 client-b 出口，两次访问隔离 exit-target Service 均超时；client-b 直接访问同一 Service 返回 ux09-subnet-target。撤回出口选择后，客户端之间普通访问恢复。没有足够证据归因 UI、Headscale 或 userspace 出口运行时，故出口数据面不通过且不列为产品 bug。
